# [music] for iPhone and iPad

The iOS app: Expo SDK 58, Expo Router, and Uniwind (Tailwind 4 for React Native) over the shared
`@music/sdk` and `@music/commands`. Screens follow the Paper pages **12–20 iOS** in the `[music]`
file. `src/global.css` keeps the Paper token names: light mode is red on white, dark mode is green
on a black canvas, and the theme follows the system.

## Develop

Native code needs a development build; Expo Go does not carry the modules this app uses. Every
native module the app will need is installed up front, so the dev client is built once and only
JavaScript changes after that. Rebuild when a dependency with native code or `app.json` changes.

From Linux, `scripts/ios-mac.sh` builds on a Mac over ssh (`MAC_HOST`, default `darwin`):

```sh
scripts/ios-mac.sh build-sim <udid>         # sync, prebuild if native inputs changed, build, install
scripts/ios-mac.sh prebuild --clean         # regenerate ios/ and pods
REACT_NATIVE_PACKAGER_HOSTNAME=<this-host> pnpm --filter mobile start --port 8082
scripts/ios-mac.sh open <udid> http://<this-host>:8082
```

The simulator loads JavaScript from Metro on this machine, so edits reload without syncing. Over
Tailscale, use this machine's Tailscale address as `<this-host>`. If the Mac can't reach the port,
forward it instead and use `127.0.0.1`: `ssh -N -R 8082:127.0.0.1:8082 darwin`. iOS asks to
confirm the first `open`; the dev client then lists the server under Recently Opened.

On a Mac, `npx expo run:ios` in this folder builds and starts Metro in one step. `ios/` is
generated by `expo prebuild` and is not committed: configure native behavior in `app.json`.

## Checks

`pnpm --filter mobile bundle` exports the iOS bundle with Metro, as CI does, so a module that
doesn't resolve fails before it reaches a phone. Uniwind regenerates `src/uniwind-types.d.ts`
whenever Metro runs; commit it, since typechecking needs it.

## Player

`src/player` makes the phone one of the user's devices. It reuses `PlaybackController` from
`@music/player`, the same device protocol the web runs, over `NativeEngine`: one expo-audio
`AudioPlayer` per stream, with the next song preloaded in a second one. Screens use the hooks in
`src/player/index.ts` and never import expo-audio. A song the server is still transcoding plays as
a live stream that can't seek, so a seek opens it again from the offset (`&start=`), or from the
finished file once the server has it.

## Downloads

`src/downloads` keeps the albums, playlists, and songs someone downloads on this phone. The server
says what each download holds (`downloads.manifest`); `DownloadSync` from `@music/sdk/downloads`
plans what to fetch and delete, and fetches finished files with `&finished=1`. It keeps each
downloaded song's lyrics too: it asks `downloads.lyrics` with the lyrics revisions it holds and
stores what changed, so Now Playing shows them with no connection. It lists them at launch
without the lyrics themselves, and reads a song's lyrics from the vault only to show them. Files and a SQLite index live
in Application Support under `downloads/<server>/<account>/`, which `modules/vault-files` marks
excluded from backup. Signing out deletes the server's downloads. Screens
use the hooks in `src/downloads/index.ts` and never see files or manifests.

To check a download on a simulator, pin it from the CLI with the phone's device ID
(`music devices list`, then `music downloads add --device-id <id> --kind album --id <albumId>`),
and look under the app's data container (`xcrun simctl get_app_container <udid> dev.lmdevv.music
data`).

## iPad

`lib/shell-layout.ts` says what frames the tabs at each window size (Paper page 26). The native tabs
stay mounted with their bar hidden, so every page keeps its stack, and `components/shell` draws a
sidebar and a player bar around them; the sidebar drives the tabs by route and reads its selection
from their navigation state. It holds library sections and playlists, which the native iPadOS
sidebar can't: that one lists tabs only. Pinned from `wide`, it hides behind a button and opens as
an overlay at `tablet`; below `tablet`, in narrow Split View, the phone's tab bar returns.

Pages take their layout from `useContentLayout`, the room beside the sidebar, not from the window.
A class's `tablet:` variant follows the window, which is fine for margins. The iPhone doesn't run
this frame at all: the device picks the tree, so a resize in Split View keeps the tabs mounted.

The Now Playing panel (`components/shell/inspector.tsx`) sits beside the content as a pane in a wide
window on its side, and above the player bar as a sheet otherwise. `lib/inspector.ts` holds its tab
and whether it is open: the shell keeps one answer per placement, so rotating neither drops a sheet
over the page nor loses the pane, and until someone picks a tab it shows the queue, then follows Now
Playing's `defaultPanel`. The bar's lyrics and queue buttons open it on that tab and hide it when lit;
the song in the bar still opens full-screen Now Playing. While that or any page covers the tabs, the
panel keeps its body, since Now Playing is see-through as it drags down, and pauses only the lyrics'
frame loop. Its Clear presents `/clear-queue`, since `/player/clear-queue` belongs to Now Playing's
own stack.

## Tab bar

iOS minimizes the tab bar and moves the mini player inline as a page scrolls, but it finds the
page's scroll view by guessing and misses most pushed pages. `modules/content-scroll` names it
instead: every page in the tabs (`TabRoot`, `Page`, `ListPage`, `SongListPage`) wraps its scroll
view in `ContentScroll`, so a new page gets the morph by using one of them.
